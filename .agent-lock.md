# .agent-lock convention

Purpose: prevent two agents from editing the same file(s) at the same time.

## How it works
1. Before editing a file (or set of files) for a non-trivial task, an agent creates
   a lock file at:
   `locks/<slug-of-target-path>.lock.json`
2. Any other agent MUST check for an existing lock before starting work on the
   same path(s), and MUST NOT edit a locked path.
3. The agent that created the lock deletes it when done (or on handoff, updates
   `expires_at` and hands ownership to the next agent via HANDOFF.md).
4. A lock older than `expires_at` is considered stale and may be broken by any
   agent — but the breaking agent must note it in HANDOFF.md.

## Lock file format
Create one JSON file per locked path (or path glob) inside `locks/`:

```json
{
  "path": "src/core/router.rs",
  "agent": "cursor",
  "task_id": "task-0042",
  "created_at": "2026-08-23T14:02:00Z",
  "expires_at": "2026-08-23T16:02:00Z",
  "reason": "refactoring routing table for v2 schema"
}
```

## Rules of thumb
- Default lock duration: 2 hours. Renew if still working; don't lock-and-forget.
- Lock the smallest scope that's true — a single file, not a whole directory,
  unless the task genuinely touches everything in it.
- If you hit a lock you need: don't break it silently. Post in Slack / check
  HANDOFF.md for context, or wait.
- Locks are advisory, not enforced by git — they only work if every agent
  actually checks `locks/` before writing. Treat skipping the check as a bug.
